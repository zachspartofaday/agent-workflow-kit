# Fictional example: Pocket Tasks CLI

Pocket Tasks has `AGENTS.md`, `DEVELOPING.md`, package scripts and numbered decisions. A user wants better handoffs while fixing a parser bug.

Keep the development guide as command owner. Verify its commands against actual configuration. Preserve the rule that credentials never enter fixtures. Link the active parser issue; a program folder and duplicate status file are unnecessary.

If the README gives a different test command, inspect current configuration and authority. If neither settles intent, ask for a decision. Never guess a package manager.

The kickoff's outcome is quoted task names round-tripping through parsing. Storage-format changes are excluded. Capture a minimal failing input, reference verified validation and review the final candidate. Keep an unrelated help-file edit untouched.

On second adoption, reuse the same owners and report no new document roles. If stale test results recur, propose a small candidate/evidence check. A full supervisor has no demonstrated benefit for this one bug.
