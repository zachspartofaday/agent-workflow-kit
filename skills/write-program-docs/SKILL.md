# Write proportional program documents

Inspect accepted requirements, current source, existing document owners and dependencies. Separate observations, assumptions and unresolved decisions. Identify implementation owners before dividing work.

Choose the smallest useful set: a task/issue for a narrow change; a compact plan and current status for a multi-step outcome; a requirements/design record plus dependency order for genuinely coordinated or high-consequence work. Do not instantiate every possible template.

State outcome, exclusions, success criteria, affected repositories, risks and rollback. Divide work into coherent deliverables whose combined acceptance preserves the parent outcome. Keep an invariant and the tests establishing it together. Record prerequisites and the integration checkpoint.

Link each repository's canonical validation owner; do not copy mutable commands. Generate only the next ready kickoff. Future slices remain provisional until source and prerequisites are current. Do not interpret sequence as execution permission.

Keep current status about active work, blockers and next action. Put completed chronology in historical records. Link a design's normative owner instead of repeating volatile facts across documents.

Return the selected document level, ownership, phase order, unresolved decisions, verification and next authorized action. Document creation does not itself authorize issues, implementation, publication or migration outside the requested scope.
