# Coordinate bounded work

Read the accepted task, repository instructions, current state and canonical command owner. Establish the actual repository/base, outcome, exclusions, dependencies, verification and existing authorization. Inspect source rather than treating a tracker assertion as implementation evidence.

If an active extension owns planning/dispatch/waiting/review, use its documented interface. Do not create a second controller. If it is unavailable, preserve the same scope and evidence rules using the host's actual capabilities; do not invent tools or background execution.

Keep the plan proportional. Resolve material decisions before dependent work, while continuing independent authorized work. Use an isolated branch/workspace where appropriate. Delegate only allowed, concrete independent tasks with bounded inputs, paths, exclusions and outputs. One writer owns a workspace.

Implement a coherent change without incidental scope expansion. Run the canonical applicable checks and inspect user-visible results where necessary. Bind each result to the candidate and relevant environment. A worker report alone does not establish correctness.

Prepare review of the completed candidate. Resolve findings, refresh affected validation and wait for a current result. Repeated same-mechanism failures call for diagnosis and a strategy checkpoint rather than indefinite patches. Stop on a real blocker with the clearing action and remaining usable work.

Report delivered scope, actual candidate, validation, review, gaps and the next authorized action. Keep merge/release/cleanup within their own authorization; do not derive it from a clean review. If specialized authoring is needed, use available skills or perform the same bounded work directly without making another skill mandatory.
