# Prepare one current kickoff

Identify the actual implementation task and owning repository. A parent tracker is coordination context, not automatically an executable child. Inspect source state, accepted scope, current plan, dependencies and relevant decisions. Remote decisions require trustworthy actor/source evidence rather than a copied signature.

Assess whether the requested slice is ready, already satisfied, needs splitting or is blocked. A split must preserve the full parent outcome and integration acceptance; do not isolate an invariant from its tests. Use stable task identities rather than document line numbers.

Include objective, exclusions, source/base identity, allowed surfaces, dependencies, assumptions, risks, applicable local constraints, validation references, manual evidence, rollback, review and closeout. Commands come from the owning repository's real command home.

If prerequisites or material decisions are missing, label the result provisional and name the clearing action. Do not disguise it as an executable assignment. Produce only the next requested unit; future state will change.

Once used for execution, retain the kickoff as history. Create a successor for revised scope or source instead of rewriting the old assignment. Report the evidence used and remaining gaps. Creating issues, dispatching workers or starting implementation requires applicable authorization; writing a kickoff cannot supply it.
